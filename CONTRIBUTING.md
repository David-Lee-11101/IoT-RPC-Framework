# Contributing

Thank you for taking the time to improve this project.

## Before opening a change

1. Search existing issues and pull requests for related work.
2. Open an issue for changes that affect public behavior, architecture, or compatibility.
3. Keep the change focused. Avoid unrelated formatting, dependency, or generated-file updates.

## Development workflow

1. Create a branch from the repository's default branch.
2. Add or update tests when behavior changes.
3. Run the repository's documented validation commands.
4. Update documentation when commands, configuration, or public behavior changes.
5. Open a pull request using the repository template and include verification evidence.

Do not commit credentials, private data, local environment files, build outputs, or IDE metadata.

## Reporting security issues

Do not post credentials, exploit details, or sensitive data in a public issue. Follow the repository's security policy and contact the owner privately.
