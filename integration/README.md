# RuleSpec v0 compatibility harness

This directory is the narrow integration boundary for four governed research repositories. It proves that one immutable RuleSpec fixture can be accepted through explicit adapters; it does not claim that the projects form a general-purpose interoperable platform.

## Contract and evidence

- [`contracts/v0/rulespec.schema.json`](contracts/v0/rulespec.schema.json) defines the shared array and device-state shape.
- [`contracts/v0/rulespec.fixture.json`](contracts/v0/rulespec.fixture.json) is the common ordered fixture. The runner records the SHA-256 of its canonical JSON bytes.
- [`capability-matrix.json`](capability-matrix.json) states what each adapter does and which semantics it omits.
- [`repositories.json`](repositories.json) records local sibling `HEAD` values with `publicationPending=true`. These are temporary provenance anchors, not published reproduction pins.
- `proof.json` is an ignored local output generated by the runner. It contains commands, repository states, normalized observations, assertions, and the capability matrix; CI uploads it as an artifact instead of committing a self-referential snapshot.

The RPC repository is the anchor. Its manifest entry deliberately uses `commitMode=invocation`: a run records the checked-out anchor commit instead of making the anchor commit contain its own hash. Sibling commits are pinned directly. Each sibling also retains its original repository slug for pre-rename CI checkout; GitHub preserves redirects after an approved rename. After publication commits are prepared, replace each sibling hash, set its pending flag to `false`, and generate the proof from clean checkouts.

## What the adapters prove

| Adapter | Source entry point | Proven boundary |
| --- | --- | --- |
| Scheduler | `SmartRuleSimulationDemo` | Every fixture rule completes in the deterministic local simulation; conditions are carried but explicitly not evaluated. |
| Analyzer | `python -m smart_rule_analyzer.cli` | Output matches ordered action-state conflict and action-to-later-input dependency semantics. |
| Composer | `python -m applet_executor.offline_composer` | Each rule is validated independently, retains its semantics, adds `schema=rule-spec/v0`, and satisfies one trigger, zero or one condition, and one action. |
| RPC | `RpcLoopbackIntegrationTest` | A real Netty/ZooKeeper loopback call returns the canonical shared fixture string exactly, verifies its pinned digest, and preserves concurrent correlation and cleanup behavior. The RPC layer does not interpret RuleSpec. |

The composer adapter intentionally materializes one temporary JSON object per rule because its source CLI accepts a single rule, while the scheduler and analyzer accept an array. This is an explicit normalization step, not evidence that arbitrary repository inputs are interchangeable.

## Run offline

Requirements: Python 3.9+, Maven, JDK 8, and the four repositories as sibling directories using their current local directory names.

From the RPC repository root:

```bash
python3 -m unittest discover -s integration/tests -v
python3 integration/compatibility.py
python3 -c 'import json; p=json.load(open("integration/proof.json")); assert p["status"] == "pass"'
```

The default command uses [`maven-settings.xml`](maven-settings.xml) and the active `JAVA_HOME` or `java` on `PATH`. Use `--java-home` when JDK 8 is installed but not active, and override repository paths only when the projects are not sibling directories. The suite uses temporary files for composer normalization and the canonical RPC payload. It makes no network call except Maven dependency resolution when artifacts are not already cached.

## CI publication gate

[`ci/compatibility.yml`](ci/compatibility.yml) is an inactive workflow template. It refuses pending revisions and clones every published sibling at the exact manifest commit. Once repository publication commits exist, finalize `repositories.json`, copy the template to `.github/workflows/compatibility.yml`, and run it from the committed anchor. The template is kept here during the pending stage so it cannot imply that unreproducible local `HEAD` values are already a public CI guarantee.
